



I have a test tool reg-rs with shell aliases like rnrg (run regression test) that many of my CLI projects used to detect regressions in CLI output after changes.  I want to integrate this with emacs so when my emacs shell is in a project I can hit a key-binding to run these tests for a project, much like some Rust/Cargo packages can run cargo test (which runs all the tests, not just these .rgt tests). look at: https://github.com/sw-cli-tools/reg-rs for details)


Thought for 15s
You want an Emacs workflow where, from a project shell or buffer, one key runs your project’s reg-rs regression tests in the same spirit as cargo test, but targeting your .rgt suites and your rnrg/related aliases.

Requirements
The pieces that matter are:

reg-rs already supports interactive shell aliases like rnrg, lsrg, shrg, uprg, etc., intended for daily use. 

rnrg can run all tests, matching tests, verbose output, quiet mode, and parallel execution. 

reg-rs auto-discovers tests from a few locations, including ./work/reg-rs/, the current directory when it contains .tdb or .rgt files, and a default local directory. 

The aliases come from bin/source-rg.sh, which is meant to be sourced from your shell rc file. 

That gives two good Emacs integration architectures:

High-level design
Option A: call the alias through a shell
Best when you want exact parity with your normal terminal behavior.

Pros

Uses the exact rnrg behavior you already trust

Respects whatever your shell alias setup does

Minimal friction

Cons

Aliases only exist in interactive/login shell contexts unless you explicitly source them

Slightly more fragile than calling the binary directly

Option B: call reg-rs directly
Best when you want robustness from Emacs.

Pros

No alias-loading issues

Easier to control from Elisp

Better for project-local automation

Cons

You must know the exact CLI subcommand shape you want

If your daily habit is rnrg, it is a tiny bit less ergonomic

For your use case, I would do both:

a default command that runs the alias via bash -lc or zsh -lc

a fallback/direct version that calls the binary if needed

Recommended behavior
Use a project-aware command that:

finds the project root

sets default-directory to that root

runs rnrg

optionally prompts for an extra filter string

displays output in a compilation buffer so next-error and standard Emacs navigation work

That gives you a clean “press key → run regression suite for current project” flow.

Low-level design
Here is a solid Emacs Lisp implementation.

Core runner
;;; reg-rs integration for Emacs

(require 'project)
(require 'compile)
(require 'subr-x)

(defgroup mike-reg-rs nil
  "Run reg-rs regression tests from Emacs."
  :group 'tools)

(defcustom mike/reg-rs-shell "bash"
  "Shell used to run reg-rs aliases."
  :type 'string
  :group 'mike-reg-rs)

(defcustom mike/reg-rs-alias-init
  "source ~/.zshrc >/dev/null 2>&1 || true"
  "Shell snippet used before invoking rnrg.
Set this to source the file that defines your reg-rs aliases.
Examples:
  \"source ~/.zshrc >/dev/null 2>&1 || true\"
  \"source ~/.bashrc >/dev/null 2>&1 || true\"
  \"source /path/to/reg-rs/bin/source-rg.sh\""
  :type 'string
  :group 'mike-reg-rs)

(defcustom mike/reg-rs-default-args ""
  "Default extra arguments passed to rnrg."
  :type 'string
  :group 'mike-reg-rs)

(defun mike/project-root ()
  "Return current project root or `default-directory`."
  (if-let ((pr (project-current nil)))
      (project-root pr)
    default-directory))

(defun mike/reg-rs--make-shell-command (args)
  "Build shell command to run rnrg with ARGS."
  (string-join
   (delq nil
         (list mike/reg-rs-alias-init
               (format "rnrg %s" (string-trim args))))
   " && "))

(defun mike/reg-rs-run (&optional args)
  "Run reg-rs tests for the current project.
With prefix arg or when called interactively with prompt, allow ARGS."
  (interactive
   (list
    (read-string
     "rnrg args: "
     mike/reg-rs-default-args)))
  (let* ((default-directory (mike/project-root))
         (cmd (mike/reg-rs--make-shell-command args))
         (full-cmd (format "%s -lc %S" mike/reg-rs-shell cmd)))
    (compilation-start full-cmd 'compilation-mode
                       (lambda (_) "*reg-rs*"))))

(defun mike/reg-rs-run-all ()
  "Run all reg-rs tests in the current project."
  (interactive)
  (mike/reg-rs-run ""))

(defun mike/reg-rs-run-verbose ()
  "Run all reg-rs tests with verbose output."
  (interactive)
  (mike/reg-rs-run "-v"))

(defun mike/reg-rs-run-failed-detail ()
  "Run all reg-rs tests with full diffs."
  (interactive)
  (mike/reg-rs-run "-vv"))

(defun mike/reg-rs-run-parallel ()
  "Run all reg-rs tests in parallel."
  (interactive)
  (mike/reg-rs-run "--parallel"))

Better shell robustness
Because aliases are shell-defined, I would usually prefer sourcing the alias file directly instead of relying on the whole shell rc:

(setq mike/reg-rs-shell "bash")
(setq mike/reg-rs-alias-init
      "source ~/src/reg-rs/bin/source-rg.sh")
That maps closely to the repo’s documented alias setup, which recommends sourcing bin/source-rg.sh from your shell config. 

This is less noisy and more deterministic than loading your full .zshrc.

  (let ((default-directory (mike/project-root)))

Smarter project detection
Since reg-rs discovers tests from several places, including ./work/reg-rs/ and the current directory when it has .rgt or .tdb files, running from the project root should usually be enough. 

If some repos keep tests below the root, add a locator:

(defun mike/reg-rs-root ()
  "Find the nearest directory suitable for reg-rs."
  (or (locate-dominating-file default-directory "work/reg-rs")
      (locate-dominating-file
       default-directory
       (lambda (dir)
         (directory-files dir nil "\\.\\(rgt\\|tdb\\)\\'")))

Then replace (mike/project-root) with (mike/reg-rs-root).

Given reg-rs already provides interactive aliases like rnrg, lsrg, shrg, uprg, rsrg, and rmrg, and it auto-discovers tests from $REG_RS_DATA_DIR, ./work/reg-rs/, the current directory when it contains .rgt/.tdb, and ~/.local/reg-rs/, the cleanest Emacs integration is to run those commands from the current project root in compilation-mode. 

Recommended architecture
Prefix map layout
I would make one top-level prefix map:

C-c p r r → run all reg-rs tests

C-c p r t → prompt for test/filter args and run

C-c p r l → list tests

C-c p r s → show one test in detail

C-c p r u → accept/rebase changed baseline

C-c p r x → reset test results

C-c p r d → delete/remove a test

C-c p r a → add/create a test

C-c p r R → rerun last reg-rs command

That keeps r as the namespace and then mostly mnemonic single letters after that.

For reg-rs, I would not bind directly to a persistent shell buffer by default. The tool is already built around short commands and summary/detail reporting, so compile/compilation-start is the better default. reg-rs supports running tests, listing status, showing details, rebasing baselines, resetting results, removing tests, and creating tests through those alias commands. 

Design choices
Why compilation-mode for reg-rs
Benefits:

ephemeral buffer

easy rerun

standard Emacs navigation

no dependence on whichever interactive shell buffer happens to be current

project-root aware

This fits especially well because reg-rs is a CLI regression tool whose main workflow is create, run, inspect, rebase, and remove tests. 

Why use aliases rather than the raw binary
The README explicitly says the shell aliases are the recommended interactive interface and gives rnrg, lsrg, shrg, uprg, rsrg, rmrg, and adrg as the intended shortcuts. 

So for Emacs, I would preserve that model and source bin/source-rg.sh before invoking commands. That gives you the exact behavior you use outside Emacs. The repo documents sourcing that file from your shell startup. 

Suggested Elisp setup
Here is a practical setup focused on reg-rs.

;;; my-reg-rs.el --- reg-rs integration under C-c p r -*- lexical-binding: t; -*-

(require 'cl-lib)
(require 'compile)
(require 'project)
(require 'subr-x)

(defgroup my-reg-rs nil
  "Run reg-rs commands from Emacs."
  :group 'tools)

(defcustom my/reg-rs-shell "bash"
  "Shell used to invoke reg-rs aliases."
  :type 'string
  :group 'my-reg-rs)

(defcustom my/reg-rs-source-command
  "source ~/src/reg-rs/bin/source-rg.sh"
  "Shell fragment that enables reg-rs aliases."
  :type 'string
  :group 'my-reg-rs)

(defcustom my/reg-rs-buffer-name "*reg-rs*"
  "Default compilation buffer name for reg-rs."
  :type 'string
  :group 'my-reg-rs)

(defvar my/reg-rs-last-command "rnrg"
  "Last reg-rs alias command run, without shell wrapper.")

(defun my/project-root ()
  "Return current project root, or `default-directory` if none."
  (if-let ((pr (project-current nil)))
      (expand-file-name (project-root pr))
    (expand-file-name default-directory)))

(defun my/reg-rs-root ()
  "Best-effort root for reg-rs execution."
  (let ((root (my/project-root)))
    (or (locate-dominating-file root "work/reg-rs")
        (locate-dominating-file
         root
         (lambda (dir)
           (directory-files dir nil "\\.\\(rgt\\|tdb\\)\\'")))
        root)))

(defun my/reg-rs--shell-command (cmd)
  "Wrap CMD in a shell that sources reg-rs aliases."
  (format "%s -lc %S"
          my/reg-rs-shell
          (format "%s && %s"
                  my/reg-rs-source-command
                  cmd)))

(defun my/reg-rs--run (cmd &optional buffer-name)
  "Run reg-rs alias CMD from project root using compilation mode."
  (setq my/reg-rs-last-command cmd)
  (let ((default-directory (my/reg-rs-root)))
    (compilation-start
     (my/reg-rs--shell-command cmd)
     'compilation-mode
     (lambda (_mode)
       (or buffer-name my/reg-rs-buffer-name)))))

(defun my/reg-rs-rerun ()
  "Rerun the last reg-rs command."
  (interactive)
  (my/reg-rs--run my/reg-rs-last-command))

(defun my/reg-rs-run-all ()
  "Run all reg-rs tests."
  (interactive)
  (my/reg-rs--run "rnrg"))

(defun my/reg-rs-run (args)
  "Run rnrg with ARGS."
  (interactive (list (read-string "rnrg args: ")))
  (my/reg-rs--run
   (string-trim (format "rnrg %s" args))))

(defun my/reg-rs-list ()
  "List tests and status."
  (interactive)
  (my/reg-rs--run "lsrg" "*reg-rs-list*"))

(defun my/reg-rs-show (args)
  "Show detailed test info via shrg."
  (interactive (list (read-string "shrg args: ")))
  (my/reg-rs--run
   (string-trim (format "shrg %s" args))
   "*reg-rs-show*"))

(defun my/reg-rs-update (args)
  "Accept changed baseline via uprg."
  (interactive (list (read-string "uprg args: ")))
  (my/reg-rs--run
   (string-trim (format "uprg %s" args))
   "*reg-rs-update*"))

(defun my/reg-rs-reset (args)
  "Reset test results via rsrg."
  (interactive (list (read-string "rsrg args: ")))
  (my/reg-rs--run
   (string-trim (format "rsrg %s" args))
   "*reg-rs-reset*"))

(defun my/reg-rs-remove (args)
  "Remove test(s) via rmrg."
  (interactive (list (read-string "rmrg args: ")))
  (my/reg-rs--run
   (string-trim (format "rmrg %s" args))
   "*reg-rs-remove*"))

(defun my/reg-rs-add (args)
  "Create a test via adrg."
  (interactive (list (read-string "adrg args: ")))

  (or (locate-dominating-file default-directory "work/reg-rs")
      (locate-dominating-file
       default-directory
       (lambda (d)
         (directory-files d nil "\\.\\(rgt\\|tdb\\)\\'")))
      (my/reg-rs-project-root)))

          my/reg-rs-shell
          (format "%s && %s" my/reg-rs-source cmd)))

(defun my/reg-rs--run (cmd &optional buffer)
  (setq my/reg-rs-last-command cmd)
  (let ((default-directory (my/reg-rs-root)))
    (compilation-start
     (my/reg-rs--cmd cmd)
     'compilation-mode
     (lambda (_) (or buffer "*reg-rs*")))))
